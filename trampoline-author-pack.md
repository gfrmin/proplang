## Part V — findings (the boundary's purchases)

**F1 — THE CHALLENGER-SERVED UTILITY (the headline).** The shipped
chooseEU serves each binary comparison ONE env built from the
CHALLENGER's assignment; both candidates' utilities read the same
served values. Consequence, demonstrated during SAT design: a
utility reading a WRITABLE name (`get "move"`) values both sides at
the challenger's value — action-dependent utilities DEGENERATE TO
TIES under the fold, always returning the option-space head. The
one-sentence route substitutes each option's OWN values by
expansion ("actions are features" done consistently), which REPAIRS
the degeneracy — and therefore diverges from the fold exactly on
Get-of-writable utilities. No frozen row pins the degenerate
behavior (every shipped world's utility follows the wire convention:
option code bound to 0, outcome + non-writable reads only). The g2
composition pin is scoped to the convention; the ruling on which
semantics is normative is the author's — register R4, OB-24.
